## 一、项目一句话介绍

**基于 Hyperledger Fabric 联盟链的地方特色食品全链路溯源系统——以保定驴肉火烧为例。**
把一头驴从养殖、检疫、屠宰、加工、冷链到门店制作驴肉火烧的全过程数据上链存证，消费者扫码可查全链路报告并验真，监管端可一键定位召回范围。

## 三、系统怎么跑起来（答辩前 10 分钟）

### 3.1 环境要求
- JDK 21、Node.js 22、MySQL 8.0（root/root）、Docker Desktop（演示 Fabric 时才需要）
- 数据库：执行 `backend/database/database.sql` 一键建库导入（库名 donkey_trace，19 张表，自带保定化演示数据）

### 3.2 启动后端（真实链）
```
cd backend
mvnw.cmd spring-boot:run "-Dspring-boot.run.arguments=--server.port=8080"
```
首次启动约 1~2 分钟（自动回放业务数据构建链账本），看到 `Started` 与 `Tomcat started on 8080` 即成功。

### 3.3 启动前端
```
cd admin-web
npm install     # 首次
npm run dev
```
浏览器打开 http://localhost:5173 —— 这是**连真后端、真账本**的完整系统。

### 3.4 启动 Fabric 联盟链（可选，演示"真链"用）
```
"D:\Git\bin\bash.exe" -l "D:/fabric/run-test-network.sh" up mychannel   # 首次（约 3 分钟）
"D:\Git\bin\bash.exe" -l "D:/fabric/deploy-chaincode.sh" go            # 首次部署链码
"D:\Git\bin\bash.exe" -l "D:/fabric/demo-tx.sh"                        # 每次演示：发起真实交易
```
若容器已存在但停了：`docker start peer0.org1.example.com peer0.org2.example.com orderer.example.com`（不要重新 up，会清账本）。

## 五、高频问题应答（背熟）

**Q：是真实上链吗？**
> 系统实现双层链：业务层为 SHA-256 链式哈希账本，12 类关键业务事件全量挂钩、秒级完整性校验；同时真实部署了 Hyperledger Fabric v2.5.16 联盟链（双组织 Peer + 排序节点 + TLS + Go 链码双组织背书），完成真实溯源交易验证，区块高度随交易增长、前后哈希严格衔接。两者均在本项目环境可现场复现。

**Q：为什么用联盟链不用公链？**
> 食品供应链参与主体身份明确、数量有限，联盟链既保证多方数据互信共治，又满足性能与隐私合规要求；Fabric 是企业级联盟链事实标准（IBM Food Trust 等在用）。

**Q：数据能改吗？**
> 改业务库任何历史数据，全链校验立即失败并定位到区块高度；链上交易无法单方删除或篡改。

**Q：和市面溯源系统区别？**
> 三点：①S→P→F 批次血缘模型支撑一键召回扩散分析；②穿透式监管工具与业务数据同源；③真实 Fabric 联盟链落地验证而非纸面方案。

更多问答见 `docs/答辩应答要点.md`。

## 七、网上同步更新方法

**GitHub 仓库**：
```
cd 项目根目录
git add -A
git commit -m "更新说明"
git push
```
（授权已缓存，推送免密）

**线上演示站（Cloudflare Pages 直传模式）**：本地重新构建后重传：
```
cd admin-web
VITE_API_MODE=mock npx vite build --outDir dist-mock --emptyOutDir
```
Cloudflare 控制台 → Workers & Pages → donkey-trace → Create deployment → 拖入 dist-mock 文件夹，一分钟生效。域名与证书无需重配。
