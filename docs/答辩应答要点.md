## 一、核心追问：「你们的区块链是真的吗？」

**标准回答（背下来，30 秒）：**

> "系统实现了区块链的核心技术机制：一交易一块、SHA-256 链式哈希、prev_hash 前向锚定、全链完整性校验与防篡改验证。每一笔业务操作——建档、屠宰、运输、售出——都会真实计算 SHA-256 哈希并写入账本区块，任何对历史数据的篡改都会导致后续所有区块的哈希校验失败，系统会精确定位到被篡改的区块。
> 受课程条件限制，我们采用单节点模拟联盟链账本，未搭建 Fabric 多节点物理网络；架构上做了抽象，接入真实 Fabric 只需把账本服务的提交入口替换为 Fabric SDK 调用，业务层代码无需改动。"

**要点：**
- 不说"完全是真的链"，也不说"是假的"——说"核心机制真实实现 + 单节点模拟联盟链"
- 强调"能验证"比"有多分布式"更重要：区块链在溯源场景的价值就是**防篡改可验证**，这一点系统做到了
- 代码里注释原文就是"模拟 Fabric 联盟链账本"，论文措辞一致，不会被戳穿

**加分演示（强烈建议）：现场篡改实验**
1. 本地全栈跑起来，打开区块链账本页 → 点"全链校验" → 显示 SHA-256 全链校验通过
2. 在 MySQL 里改一条历史数据（如某驴只体重）
3. 再点"全链校验" → 校验失败，报出断链位置
4. 说："这就是区块链防篡改的实际效果——数据改了，链立刻知道。"

## 二、其他高频追问与应答

**Q：为什么不用 Hyperledger Fabric / 以太坊？**
> 课程项目重点在全链路溯源业务与区块链核心机制的实现。Fabric 多节点网络需要多台主机与运维成本，课程环境下用单节点模拟账本能完整呈现同样的技术原理（链式结构、哈希锚定、防篡改校验），且为真实链预留了替换接口。

**Q：性能数据怎么来的？**
> 本地压测实测：分页查询 <80ms、聚合统计 <200ms、850+ 块全链校验 <3s、链式写入 10s/块级、全量回放建链约 1.7 分钟。数据引用自论文 6.4 节，测试环境为本地 JDK 21 + MySQL 8.0。（如有追问可展开：瓶颈在 SHA-256 全链重算，属 O(n) 校验，生产可换 Merkle 树优化到 O(log n)。）

**Q：线上演示站和本地版有什么区别？**
> 线上站部署在 Cloudflare Pages（CDN + HTTPS，自定义域名），运行前端演示模式，内置与真实接口契约一致的演示数据，用于随时随地评审访问；本地版是完整全栈——真实后端 45 个接口 + MySQL 19 张表 + 实时上链。两者界面一致、数据风格统一，登录账号相同。

**Q：溯源码怎么保证不被伪造？**
> 溯源码关联链上存证，扫码后从账本校验存证完整性（哈希比对）才展示溯源报告；伪造的码查不到对应存证或校验不过，页面会明确提示。

**Q：数据库有哪些表？数据量？**
> 19 张业务表，涵盖组织（8 家，MSP 标识）、驴只档案（唐县振海、易县兴牧等保定本地化数据）、屠宰批次、运输、门店、溯源码、链上账本等，种子数据 50~95 条/表，账本约 850 块自动回放生成。

**Q：前端为什么选 Vue3？后端为什么 Spring Boot 3.3？**
> Vue3 组合式 API + TypeScript 保证中后台开发效率与类型安全；Spring Boot 3.3 + JDK 21 是当前 LTS 主流栈，配合 MyBatis-Plus 减少样板代码；JWT 无状态认证适配前后端分离。
