## 1. 项目概述

### 1.1 项目背景

驴肉火烧是华北地区代表性特色小吃（保定漕河派、河间派），行业长期存在以下痛点：

| 痛点 | 具体表现 |
|------|---------|
| **以次充好** | 用马肉、骡肉、猪肉、廉价禽肉冒充驴肉，消费者无法辨别 |
| **来源不明** | 驴肉来源渠道混杂，无正规检疫证明的情况时有发生 |
| **冷链断链** | 运输储存温度不达标，肉品变质风险无法追溯 |
| **监管困难** | 监管部门抽检数据分散、纸质证明易伪造、难穿透全链条 |
| **信任缺失** | 门店招牌"正宗驴肉"无法自证，劣币驱逐良币 |

### 1.2 项目目标

构建一条 **"养殖 → 检疫 → 屠宰 → 加工 → 冷链物流 → 门店 → 消费者扫码"** 的全链路溯源体系：

1. **数据可信**：关键溯源事件实时上链（Hyperledger Fabric 联盟链），链上数据不可篡改、可验证；
2. **一物一码**：每份成品（火烧用驴肉/火烧）绑定唯一溯源码，消费者扫码即可看到全链路流转记录与区块链存证信息；
3. **多方协作**：养殖场、屠宰加工厂、物流商、门店、监管部门以联盟链成员身份各司其职，数据按权限共享；
4. **监管穿透**：监管部门可对任意批次一键回溯全链路，异常自动预警，支持批次级召回。

### 1.3 建设范围

- **一期（MVP）**：Fabric 测试网络 + 核心链码 + 后端服务 + 运营/企业 Web 端 + 消费者扫码 H5，跑通"建档→屠宰→加工→门店→扫码"模拟闭环；
- **二期**：监管端与数据大屏、冷链 IoT 温湿度自动采集对接、微信小程序、证照审核流程；
- **三期**：生产级多机部署（多组织多 peer）、私有数据集合（隐私保护）、IoT 设备管理、性能压测与安全加固。

### 1.4 设计原则

- **链上链下协同**：链上只存关键事件（摘要字段 + 详情哈希），大文件（图片、检测报告 PDF）存对象存储 MinIO，兼顾不可篡改与存储成本；
- **极简录入**：一线操作人员（养殖员、门店店员）文化水平参差，录入界面以"扫码 + 点选 + 拍照"为主，杜绝自由文本必填；
- **先模拟后对接**：IoT 温湿度先支持手工/文件导入，二期再对接真实设备，降低初期联调风险；
- **AI 开发友好**：模块边界清晰、接口契约完整、每个模块可独立交给 AI 实现（详见第 16 章）。

## 2. 术语表

| 术语 | 说明 |
|------|------|
| **Fabric** | Hyperledger Fabric，Linux 基金会开源企业级联盟链平台，本项目采用 2.5 LTS |
| **联盟链** | 由多个已知组织共同维护的许可链，与公链（如以太坊）相对 |
| **组织（Org）** | 联盟链成员单位，如养殖场组织、加工厂组织、监管组织 |
| **MSP** | Membership Service Provider，成员身份管理，每个组织一个 MSP，链码通过 MSP ID 判断调用者身份 |
| **Peer** | 组织内的区块链节点，持有账本副本、执行链码 |
| **Orderer（排序节点）** | 负责交易排序打包出块，本项目采用 Raft 共识 |
| **链码（Chaincode）** | Fabric 智能合约，本项目用 Go 语言编写 |
| **通道（Channel）** | 组织间的私密"子链"，本项目使用单一主通道 |
| **交易（Tx）** | 一次对账本的写操作，成功后生成交易 ID（txId）并永久记录 |
| **耳标号（earTagId）** | 驴只个体唯一标识（RFID/二维码耳标），形如 `E6401-2026-000123` |
| **批次（Batch）** | 肉品流转的基本单位，分屠宰批次/加工批次/成品批次，子批次记录父批次实现批次树 |
| **溯源码** | 绑定成品批次的唯一二维码，消费者扫码入口，形如 16 位防伪码 + 活码 URL |
| **链上链下** | 链上=Fabric 账本（关键事件+哈希）；链下=MySQL/MinIO（明细数据+大文件） |
| **BaaS** | Blockchain as a Service，链的托管运维方式（本项目自建 Docker 部署，非 BaaS） |

| 数据 | 存储位置 | 内容 |

| 用户/角色/权限等系统数据 | 仅链下 | 与溯源无关，不上链 |

## 4. 角色与权限体系

### 4.1 联盟组织 × 系统角色矩阵

| 联盟组织（Fabric Org） | MSP ID | 系统角色（RBAC） | 核心职责 |
|------------------------|--------|------------------|---------|
| 平台运营方 | OrgPlatform-MSP | `PLATFORM_ADMIN` | 联盟治理：组织准入、用户管理、溯源码规则、参数配置 |
| 养殖场 | OrgFarm-MSP | `FARM_OPERATOR` `FARM_MANAGER` | 驴只建档、饲喂/免疫记录、出栏检疫申请 |
| 屠宰加工厂 | OrgPlant-MSP | `PLANT_OPERATOR` `PLANT_QC` | 屠宰批次、分割/卤制加工批次、出厂检验 |
| 物流商 | OrgLogistics-MSP | `LOGISTICS_DRIVER` `LOGISTICS_DISPATCHER` | 运输单、温湿度记录、交接签收 |
| 门店 | OrgShop-MSP | `SHOP_KEEPER` | 收货验收、库存、成品制作、溯源码绑定、销售 |
| 监管部门 | OrgRegulator-MSP | `REGULATOR_OFFICER` `REGULATOR_ADMIN` | 证照审核、抽检登记、预警处置、召回发起 |
| 消费者 | —（不上链身份） | `CONSUMER`（匿名） | 扫码查询、投诉反馈 |

### 4.2 权限控制三层模型

1. **网关层**：JWT 携带 `orgType + role`，Spring Security 按 URL 前缀拦截（如 `/api/v1/regulator/**` 仅监管角色）；
2. **服务层**：业务校验"当前组织是否拥有该数据"（如门店只能操作自己名下的批次）；
3. **链码层（最终防线）**：链码内通过 `ctx.GetClientIdentity().GetMSPID()` 校验操作合法性——例如只有 `OrgFarm-MSP` 能调用 `CreateDonkey`，只有 `OrgRegulator-MSP` 能调用 `RecallBatch`。**即使后端被攻破，链上数据也无法被越权写入**。

### 4.3 权限-菜单映射（前端动态路由依据）

| 菜单 | 权限码 | 可见角色 |
|------|--------|---------|
| 联盟管理 / 组织用户 | `org:manage` | PLATFORM_ADMIN |
| 驴只档案 / 建档录入 | `donkey:write` | FARM_* |
| 屠宰管理 | `batch:slaughter` | PLANT_OPERATOR |
| 加工管理 | `batch:process` | PLANT_OPERATOR |
| 出厂检验 | `qc:report` | PLANT_QC |
| 运输管理 | `transport:manage` | LOGISTICS_* |
| 门店收货 / 库存 | `shop:stock` | SHOP_KEEPER |
| 溯源码生成绑定 | `code:bind` | SHOP_KEEPER |
| 证照管理 | `cert:manage` | 各组织管理员 |
| 监管审核 / 抽检 | `regulator:audit` | REGULATOR_* |
| 召回管理 | `regulator:recall` | REGULATOR_ADMIN |
| 数据大屏 | `stats:screen` | REGULATOR_*, PLATFORM_ADMIN |

## 5. 核心业务流程

### 5.1 全链路主流程（溯源主线）

```
【养殖场】                【屠宰加工厂】            【物流商】              【门店】            【消费者】
 建立驴只档案(耳标)   →   核对耳标/宰前检疫    →   创建运输单         →   收货验收         →   扫码
 饲喂/免疫记录上链        屠宰→生成屠宰批次         装车绑批次             入库                溯源时间轴
 出栏检疫合格证明         分割/卤制→加工批次        温湿度定时记录          制作火烧领用批次      区块链存证验证
                         出厂检验→成品批次         在途GPS(可选)          生成并绑定溯源码      投诉反馈
                                                  卸车签收               扫码销售
     └────────────────── 每一步关键事件同步上链（txId 存证）──────────────────┘
                                        ↓
                          【监管部门】证照审核 / 抽检 / 预警处置 / 召回
```

### 5.2 批次树模型（核心概念）

驴肉从一头驴到一份火烧，经历"批次分裂"，用**父子批次关系**构成批次树：

```
驴只个体 E6401-2026-000123          E6401-2026-000124
      │                                │
      └──────────┬─────────────────────┘
                 ▼
   屠宰批次 S-20260911-001（含2头驴）
                 │ 分割
        ┌────────┴────────┐
        ▼                 ▼
  加工批次 P-20260911-001  加工批次 P-20260911-002（后腿肉/肋条）
        │ 卤制              │
        ▼                  ▼
  成品批次 F-20260911-001  成品批次 F-20260911-002
        │                  │
        ▼                  ▼
  门店A 溯源码×200张     门店B 溯源码×150张
  (DT9F3K2A8Q7M5X1P ...) (DT...)
```

规则：
- 每个批次上链记录 `parentIds`，溯源时从成品批次沿 `parentIds` 递归回溯到驴只个体；
- 屠宰批次的 `sourceDonkeys` 记录耳标号数组，实现"肉 ↔ 活体"映射；
- 一个成品批次可拆分为多个销售单元（溯源码），每个码对应一份火烧的肉量（如 150g）。

### 5.3 批次状态机

```
CREATED(创建) → IN_TRANSIT(在途) → RECEIVED(已签收) → IN_STORE(在库)
      → SOLD(已售罄/码售完)
CREATED/IN_TRANSIT/IN_STORE → RECALLED(召回中，监管触发)
任意状态 → EXPIRED(超过保质期，定时任务置位)
```

状态变更只能由**持有时组织**发起且上链，非法跃迁链码直接拒绝。

### 5.4 关键环节详细流程

**F1 驴只建档**：养殖员 PDA 扫耳标 → 表单（品种/月龄/性别/圈舍，全部点选）→ 拍照 → 提交 → 后端生成驴只记录 + 调链码 `CreateDonkey` → 返回 txId → 档案列表显示"已上链"徽标。

**F2 出栏检疫**：官方兽医开具《动物检疫合格证明》（动物A证）→ 养殖场上传证明照片/PDF → 系统算文件哈希 → 链码 `QuarantineDonkey` 写入证号+哈希 → 证照进入监管待审核池（二期启用审核流，一期直接生效）。

**F3 屠宰与批次生成**：加工厂收驴核对耳标 → 宰前检疫（链上记录）→ 屠宰 → 按胴体生成分割批次，选择"来源屠宰批次"（扫码选择而非手输）→ 每个分割批次记录分割部位、重量、操作人 → QC 出厂检验合格后创建成品批次（含保质期）。

**F4 冷链运输**：调度创建运输单（选成品批次、目的门店、车辆、司机）→ 链码 `TransferBatch` 批次状态置 IN_TRANSIT → 在途每 30 分钟记录温湿度（一期手工/PDA 录入，二期传感器自动上报）→ 到店司机+门店店员双签收 → 链码 `ReceiveBatch`。温控超标自动触发预警（见第 12 章）。

**F5 门店与销售**：店员确认收货入库 → 制作火烧时"领用"成品批次（扣减库存重量）→ 每炉成品出锅，批量生成溯源码并绑定该批次的"产出记录"（记录出锅时间、烤制师傅）→ 顾客购买后扫码即见完整链路。

**F6 消费者扫码**：微信/相机扫码 → H5 加载聚合溯源报告（时间轴形式）→ 报告底部展示区块链存证信息（通道名、交易 ID、区块高度）与"已验证"绿标 → 可选匿名投诉。

**F7 召回（监管）**：监管输入批次号 → 系统展示该批次下游全部去向（门店、码、已扫记录）→ 确认召回 → 链码 `RecallBatch` 递归标记 → 相关组织工作台红色提醒 → 生成召回报告 PDF。

### 6.1 模块总览

| 编号 | 模块 | 端 | 优先级 |

### 6.2 M01 认证与用户中心

**功能点**
- 账号密码登录（JWT，双 token：access 2h / refresh 7d）
- 组织切换提示（一人多组织场景一期不支持，一账号只属一组织）

**页面**：登录页、403/404 页、个人中心、修改密码

**关键规则**

- 所有业务接口要求登录（除 `/api/v1/trace/{code}` 公开接口与登录接口）
- 用户创建时由平台管理员操作，同时调用 Fabric CA 为其所在组织注册可选的链上身份（一期可由组织网关统一代理签名，简化部署）

### 6.3 M02 组织与联盟管理

**功能点**
- 组织列表/详情（组织类型、MSP ID、联系人、状态：待启用/正常/停用）
- 新增组织（平台管理员操作：录入信息 → 后端执行 Fabric CA 生成组织管理员证书 → 注册 MSP → 加入通道，一期提供"模拟模式"在 test-network 预置）
- 组织下用户管理：新增、禁用、重置密码、分配角色
- 联盟公告（链下）

**页面**：组织列表、组织编辑、用户列表、用户编辑

### 6.4 M03 驴只档案管理（养殖端）

**功能点**
- 驴只列表：筛选（耳标号/品种/状态/圈舍），状态徽标（饲养中/已检疫/已屠宰）
- 新建档案：耳标号（PDA 扫码或手输）、品种（下拉：德州驴/关中驴/新疆驴/杂交）、性别、出生日期、圈舍编号、照片
- 饲喂记录：日期、饲料类型（点选：牧草/玉米/豆粕/混合）、饮水情况、备注、照片 → 上链（摘要）
- 免疫记录：疫苗名称（点选：马传贫/破伤风/口蹄疫等）、接种日期、疫苗批号、兽医签字、照片 → 上链
- 出栏检疫：上传《动物检疫合格证明》→ 证号 + 文件哈希上链 → 驴只状态变为"已检疫"
- 档案详情页：基本信息 + 事件时间轴 + 每条事件显示 txId 与区块高度
- 批量导入：Excel 模板导入耳标（建档），导入结果校验报告

**关键规则**
- 耳标号全局唯一，格式 `E{区县代码4位}-{年份}-{6位流水}`，服务端校验正则 `^E\d{4}-\d{4}-\d{6}$`
- 已屠宰驴只档案**只读**，任何修改留痕为追加事件而非覆盖
- 链上 `CreateDonkey` 失败则整个建档回滚（链下数据同时回滚，保证一致性）

### 6.5 M04 屠宰与加工批次管理（加工厂端）

**功能点**
- 屠宰批次管理：创建（选择来源驴只——扫耳标多选、屠宰日期、宰前检疫记录、屠宰车间）→ 上链
- 分割批次：选择屠宰批次 → 录入分割品（部位点选：里脊/肋条/后腿/前腿/脖肉/杂碎）、重量、分割批次号自动生成 → 上链
- 卤制/加工批次：选择分割批次 → 老汤批次、添加剂清单（点选国家允许目录，必填证明）、卤制时长温度 → 上链
- 出厂检验（QC 角色）：检验项目清单（感官/水分/兽残快检/瘦肉精）、结论、报告 PDF 上传 → 哈希上链 → 成品批次生成
- 批次列表与详情：批次树可视化（父子层级展示）、当前状态、当前持有人

**关键规则**
- 批次号规则：`S-{yyyyMMdd}-{3位流水}`（屠宰）、`P-`（加工分割）、`F-`（成品）；流水按组织独立递增
- 屠宰批次必须关联至少 1 头"已检疫"状态的驴只，否则链码拒绝
- 成品批次必须关联检验合格记录（certHash 非空）才能进入流转
- 成品批次必须填写保质期（默认冷藏 7 天）

### 6.6 M05 冷链物流管理（物流端）

**功能点**
- 运输单创建：选成品批次（扫码）、起运组织、目的门店、车牌、司机、预计到达时间 → 批次状态置 IN_TRANSIT 并上链
- 温湿度记录：在途列表 → 记录（时间、温度℃、湿度%、照片）→ 支持单条与批量（Excel 导入）；每次记录生成 `recordHash`，运输**完结时**将全部记录打包文件上传 MinIO，文件哈希一次性上链（减少链上交易量）
- 在途 GPS（可选）：每条记录可附带经纬度，H5 详情显示地图轨迹（二期）
- 电子签收：门店确认收货 → 双方签名记录上链 → 批次状态 RECEIVED
- 异常记录：温度超标的记录自动标红并触发预警

**关键规则**
- 温度阈值按品类配置：鲜驴肉 0~4℃；卤制品 0~4℃；冷冻品 ≤-18℃（参数表可配）
- 运输单创建前校验：批次状态必须 CREATED、当前持有组织=发起组织
- 链上 `TransferBatch` 校验调用方 MSP=发货组织，`ReceiveBatch` 校验 MSP=收货组织

### 6.7 M06 门店收货与销售管理（门店端）

**功能点**
- 收货工作台：待收货列表（运输单）→ 逐批次确认（核对重量、温度、感官）→ 签收/拒收（拒收需拍照说明，触发预警）
- 库存管理：在库成品批次列表（剩余重量、入库时间、保质期倒计时）、临期标黄（剩余<30%保质期）、过期标红并禁止领用
- 火烧制作：选择在库批次 → 领用重量 → 生成"产出记录"（炉次、时间、师傅、成品数量估算）
- 溯源码管理：为产出记录批量生成溯源码（选数量）→ 打印（支持 PDF 导出、标签模板 60×40mm）→ 绑定批次产出关系 → 码状态流转
- 销售记录（可选轻量）：扫码销售确认，用于统计与"码售完"状态

**关键规则**
- 一码 = 一份成品（一份火烧的驴肉量），码绑定"成品批次+门店+产出记录"，绑定关系上链
- 码状态机：`UNUSED(已生成未打印) → BOUND(已绑定产出记录) → SOLD(售出) → DESTROYED(作废)`
- 溯源码生成算法：`DT` + 14 位随机大写字母数字（去掉易混 0O1I），唯一索引防重
- 活码 URL：`https://{domain}/t/{code}`，二维码内容即该 URL，短链稳定可换 H5 版本

### 6.8 M07 溯源引擎与一物一码（核心服务）

**功能点**
- **溯源报告聚合**：输入溯源码 → 查绑定关系 → 取成品批次 → 沿批次树回溯 → 汇集全部链上事件（按时间排序）→ 合并链下详情（图片 URL、文件链接）→ 输出结构化 JSON 供 H5 渲染
- **存证验证**：对每个链上事件重算详情哈希（链下文件 SHA-256）与链上 `detailHash` 比对 → 全部通过则报告打"已验证"绿标
- **码池管理**：平台可预生成码池供门店申领（二期）；一期门店即时生成
- **防伪风控**：扫码日志（IP/地区/UA/时间）→ 异常规则（24h>50 次、跨省跳跃）→ 标记可疑并在 H5 提示"该码被异常高频查询，请核实购买渠道"
- **批次溯源图**：后台可视化批次树（D3/ECharts tree 图），节点点击显示事件

### 6.9 M08 消费者扫码查询 H5

**功能点**
- 无需登录，扫码直达
- 溯源报告（移动端时间轴 UI）：
  - 顶部：产品名（驴肉火烧·卤制驴肉）、门店、出锅时间、验证状态徽标
  - 时间轴节点：养殖（养殖场名、品种、入栏日期）→ 免疫/检疫（证明证号）→ 屠宰（批次号、日期）→ 分割/卤制 → 出厂检验 → 冷链运输（全程温度区间）→ 门店收货 → 制作出锅
  - 每节点：企业名称、时间、摘要、可展开图片、**txId 短码**
  - 底部：区块链存证卡片（通道、最新区块高度、事件数、"链上数据自上链起不可篡改"说明）
- 防伪提示位（可疑码黄色警示条）
- 一键投诉：类别（怀疑非驴肉/变质/卫生/其他）+ 描述 + 照片 → 生成投诉单推送监管端（匿名，可留手机号）
- 分享：生成带品牌水印的溯源海报图（canvas 合成，二期）

### 6.10 M09 证照管理

**功能点**
- 证照台账：类型（营业执照/食品经营许可证/动物防疫条件合格证/检验检测资质）、证号、有效期、附件

## 7. Fabric 联盟链网络设计

### 7.1 网络拓扑（一期 test-network 起步，生产同构扩展）

```
Raft Orderer ×3:  orderer1/2/3.example.com
组织 ×5（每组织：peer×2 + Fabric CA×1 + cli）:
  Org-Farm       peer0.farm.example.com        MSP: OrgFarmMSP
  Org-Plant      peer0.plant.example.com       MSP: OrgPlantMSP
  Org-Logistics  peer0.logistics.example.com   MSP: OrgLogisticsMSP
  Org-Shop       peer0.shop.example.com        MSP: OrgShopMSP
  Org-Regulator  peer0.regulator.example.com   MSP: OrgRegulatorMSP
平台后端作为 Org-Shop/各组织的客户端通过 Gateway 连接（一期单网关代理全部组织，二期每组织独立网关）
```

- 通道：`donkey-channel`，所有组织加入
- 背书策略：`MAJORITY Endorsement`（5 组织中 3 个），关键函数可收紧（如召回需 Regulator + 目标组织）
- 账本：`assettrace` 链码，状态数据库 LevelDB（一期）/ CouchDB（生产，支持富查询）
- **一期简化**：test-network 默认 2 组织，新增第 3~5 组织用脚本扩展；提供 `deploy/fabric/` 下全套 compose 与脚本，`./network.sh up` 一键拉起

### 7.2 链码数据模型（Go struct，JSON 存储键值）

```
Donkey      key: KEY~EAR~{earTagId}
Batch       key: KEY~BAT~{batchId}
TraceEvent  key: EVT~{targetId}~{seq}   （复合键，按对象聚合、按序排列）
TraceCode   key: KEY~CODE~{code}        （code → batchId 映射，绑定关系上链）
Alert       key: KEY~ALERT~{alertId}
```

字段定义见第 8 章链码源码级设计。

### 7.3 上链时机与批量策略

| 动作 | 上链方式 | 说明 |
|------|---------|------|
| 驴只建档 | 单笔提交 | 低频、关键 |
| 饲喂/免疫记录 | 单笔（摘要） | 高频但价值高；若压力大可按日聚合为 1 笔 |
| 批次创建/流转/签收 | 单笔 | 必须实时 |
| 温湿度明细 | **运输完结打包 1 笔**（文件哈希） | 控制交易量 |
| 码绑定 | 产出单打包 1 笔（码数组） | 避免一码一交易 |

### 7.4 链上隐私与扩展点（三期）

- 私有数据集合（PDC）：养殖场配方等敏感数据走 `{OrgFarm}PrivateCollection`，链上只留哈希；
- 状态基背书（SBE）：批次流转要求当前持有组织背书；
- 多通道：未来按省份拆分通道横向扩展。

## 8. 智能合约（链码）设计

> 链码名 `assettrace`，Go 1.22 + fabric-contract-api-go，单合约多事务。以下为**源码级契约**，AI 可直接按此实现。

### 8.1 数据结构定义

```go
type Donkey struct {
    DocType    string   `json:"docType"`    // "donkey"
    EarTagID   string   `json:"earTagId"`   // 主键
    Breed      string   `json:"breed"`      // 品种
    Gender     string   `json:"gender"`     // M/F
    BirthDate  string   `json:"birthDate"`  // yyyy-MM-dd
    FarmOrgID  string   `json:"farmOrgId"`  // MSP ID
    FarmName   string   `json:"farmName"`
    Status     string   `json:"status"`     // RAISED | QUARANTINED | SLAUGHTERED
    CreateTime string   `json:"createTime"` // RFC3339
    UpdateTime string   `json:"updateTime"`
}

type Batch struct {
    DocType       string   `json:"docType"`      // "batch"
    BatchID       string   `json:"batchId"`      // 主键 S-/P-/F- 前缀
    BatchType     string   `json:"batchType"`    // SLAUGHTER | PROCESS | PRODUCT
    ParentIDs     []string `json:"parentIds"`    // 父批次（溯源树）
    SourceDonkeys []string `json:"sourceDonkeys"`// 仅屠宰批次：耳标数组
    OwnerMSP      string   `json:"ownerMsp"`     // 创建组织
    HolderMSP     string   `json:"holderMsp"`    // 当前持有组织
    ProductName   string   `json:"productName"`  // 如 卤制驴肉(后腿)
    WeightKg      float64  `json:"weightKg"`
    ProduceDate   string   `json:"produceDate"`
    ExpireDate    string   `json:"expireDate"`   // 仅成品批次
    CertHash      string   `json:"certHash"`     // 检疫/检验证明哈希
    Status        string   `json:"status"`       // CREATED|IN_TRANSIT|RECEIVED|IN_STORE|SOLD|RECALLED|EXPIRED
    CreateTime    string   `json:"createTime"`
    UpdateTime    string   `json:"updateTime"`
}

type TraceEvent struct {
    DocType    string `json:"docType"`   // "traceEvent"
    EventID    string `json:"eventId"`   // UUID
    TargetID   string `json:"targetId"`  // batchId 或 earTagId
    EventType  string `json:"eventType"` // 枚举见 8.3
    OrgMSP     string `json:"orgMsp"`    // 事件发生组织（=客户端 MSP）
    Operator   string `json:"operator"`  // 操作人账号
    Timestamp  string `json:"timestamp"` // RFC3339
    Summary    string `json:"summary"`   // ≤200字摘要（链上明文）
    DetailHash string `json:"detailHash"`// 链下详情文件 SHA-256
    DetailURI  string `json:"detailUri"` // MinIO 地址
}

type TraceCode struct {
    DocType   string `json:"docType"`  // "traceCode"
    Code      string `json:"code"`     // 主键 DT+14位
    BatchID   string `json:"batchId"`  // 绑定成品批次
    ShopMSP   string `json:"shopMsp"`  // 绑定门店
    OutputID  string `json:"outputId"` // 门店产出记录 ID
    Status    string `json:"status"`   // BOUND | DESTROYED
    BindTime  string `json:"bindTime"`
}

type Alert struct {
    DocType   string `json:"docType"`
    AlertID   string `json:"alertId"`
    TargetID  string `json:"targetId"`
    AlertType string `json:"alertType"` // TEMP_EXCEED | CERT_EXPIRED | FAKE_SCAN | OVERDUE | QUARANTINE_MISS
    Level     string `json:"level"`     // INFO | WARN | CRITICAL
    Summary   string `json:"summary"`
    RaiseMSP  string `json:"raiseMsp"`
    RaiseTime string `json:"raiseTime"`
    Status    string `json:"status"`    // OPEN | RESOLVED
}
```

### 8.2 链码函数清单（含权限与状态校验）

| # | 函数 | 签名（关键参数） | 允许 MSP | 校验规则 | 事件（ChaincodeEvent） |
|---|------|----------------|----------|---------|----------------------|
| 1 | CreateDonkey | earTagId, breed, gender, birthDate, farmName | OrgFarmMSP | 耳标不存在；正则校验 | DonkeyCreated |

## 10. API 接口设计

### 10.1 全局约定

- Base URL：`/api/v1`；JSON；统一响应体：

```json
{ "code": 0, "message": "ok", "data": { }, "traceId": "uuid" }
```

- 错误码：`0` 成功；`40xxx` 认证/权限；`50xxx` 业务（如 `50001 批次状态不允许该操作`）；`60xxx` 区块链（`60001 链码执行失败`，message 附链码 ERR 前缀原文）

- 分页：`?page=1&size=20`，返回 `{total, records}`

## 11. 溯源码与消费者查询设计

### 11.1 码体系

- **码值**：`DT` + 14 位（大写字母+数字，剔除 0/O/1/I），如 `DT9F3K2A8Q7M5X1`；生成用 `SecureRandom`，库内唯一索引兜底
- **二维码内容**：`https://trace.donkeychain.cn/t/DT9F3K2A8Q7M5X1`（H5 域名可配置）
- **标签规格**：默认 60×40mm 铜版纸不干胶；打印模板含品牌 Logo、产品名、"扫码验证驴肉真源"文案、二维码；支持导出 PDF（A4 排版 6×3）供普通打印机
- **安全性**：码不含有序信息不可预测；H5 不暴露内部 ID，只按码查询；删除/作废码后扫码显示"该码已作废"

### 11.2 扫码防刷与风控

| 规则 | 阈值 | 动作 |
|------|------|------|
| 单 IP 频率 | >10 次/分钟 | 429 + 验证码挑战（二期） |
| 单码 24h 扫描 | >50 次 | 标记风险，H5 黄条提示 |
| 跨省短时跳跃 | 1h 内跨省 | 标记风险 |
| 码状态为 DESTROYED | — | H5 显示作废页 |

### 11.3 H5 页面结构（consumer-h5）

```
/t/:code   溯源报告（时间轴 + 存证卡片 + 投诉按钮）
/invalid   作废/不存在
/error     网络错误重试
```

性能要求：报告接口 P95 < 800ms（Redis 缓存报告 JSON，TTL 5 分钟，批次事件更新时主动失效）。

## 12. 预警与监管设计

### 12.1 预警规则表（sys_config 可调）

| 规则编码 | 触发条件 | 级别 | 通知对象 |
|---------|---------|------|---------|
| TEMP_EXCEED | 温度记录超阈值 | WARN | 物流商+门店+监管 |
| CERT_EXPIRED | 证照到期前30/7天 | INFO→WARN | 企业+监管 |
| OVERDUE | 成品批次超保质期未售罄 | WARN | 门店+监管 |
| QUARANTINE_MISS | 屠宰批次关联驴只未检疫（链码已拦截，此为链下兜底扫描） | CRITICAL | 监管 |
| FAKE_SCAN | 码风控命中 | INFO | 平台+监管 |
| REJECT_RECEIPT | 门店拒收 | WARN | 加工厂+监管 |
| COMPLAINT_NEW | 新投诉 | INFO | 监管 |

### 12.2 预警产生路径

1. **同步即时**：业务动作触发（拒收、温度超标单条）→ 服务层直接写 biz_alert + 链码 RaiseAlert（WARN 及以上上链）；
2. **定时扫描**：每 10 分钟任务（过期批次、证照到期），每小时（风控汇总）。

## 13. 非功能性需求

| 类别 | 指标 |
|------|------|
| 性能-接口 | 核心查询 P95 < 500ms；溯源报告 P95 < 800ms；上链写操作 P95 < 3s（含出块等待） |
| 性能-链 | 一期按 50 TPS 持续写入设计（远低于 Fabric 上限），峰值 500 TPS 可通过背书节点扩容支撑 |
| 并发 | 扫码峰值 200 QPS（节假日），H5 走 Redis 缓存与 CDN 静态资源 |
| 可用性 | 业务服务双实例无状态部署；MySQL 主从；链 5 组织各 2 peer，单 peer 故障不影响读写 |
| 安全 | 全站 HTTPS；JWT 过期+刷新机制；越权测试用例纳入验收；MinIO 私有桶+预签名 URL（7 天有效）；操作日志防篡改（定期哈希快照上链，三期） |
| 审计 | 全量操作日志保留 ≥3 年；链上数据天然永久 |
| 备份 | MySQL 每日全备+binlog；链数据 peer 各自持久卷；MinIO 版本化桶 |
| 合规 | 符合《食品安全法》第42条追溯义务、《动物防疫法》检疫证明管理、《数据安全法》；溯源报告作为消费纠纷证据时提供"链上存证校验"功能 |

### 16.3 编码规范（AI 生成时强制）

- Java：阿里巴巴 Java 开发手册；实体 `BizXxx`，DTO `XxxDTO`，Service 接口+impl；所有链上交互必须收敛在 `fabric/` 包，业务 Service 只调 `FabricGatewayClient`
- Go：标准 gofmt；链码错误一律 `ERR_XXX` 前缀；禁止在链码中引入第三方状态存储
- Vue：`<script setup lang="ts">`；API 层按模块文件拆分；Element Plus 组件名全量引入无需按需（简化 AI 生成）
- SQL：表名 `sys_/biz_` 前缀小写下划线；所有表含 create_time/update_time；逻辑删除用 status 而非物理删除（除日志表）
- Git：分支 `feat/T{n}-{name}`；commit message 遵循 Conventional Commits

### 16.4 联调与验收数据流自检清单

- [ ] 每个上链动作都能在响应中拿到 txId，并在链下表落库
- [ ] 链码拒绝的越权操作（如门店调用 CreateDonkey）返回 `60001` 且链上状态无变化
- [ ] 停掉 fabric 网络后，业务接口上链类操作超时回滚，链下无脏数据（事务一致性）
- [ ] 任意码的报告时间轴与批次树人工核对一致
- [ ] 召回后所有下游码扫码可见召回提示

## 17. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| Fabric 部署/运维复杂 | 一期进度 | 全容器化+一键脚本；先 test-network 单机；提供降级开关（链不可用时业务缓存排队重投，见 16.4） |
| **源头数据造假**（链只保证上链后不可改，不保证录入为真） | 信任根基 | ① 关键节点强制附件（检疫证明照片）+监管抽查；② 多组织互证（签收方确认发货记录）；③ IoT 自动采集替代手工（三期）；④ H5 明示"数据由联盟成员共同维护" |
| 企业录入意愿低 | 数据断链 | 界面极简（扫码+点选）、Excel 批量导入、录入动作与必要业务动作合并（签收即录入） |
| 扫码高峰打爆报告接口 | 体验 | Redis 报告缓存 + CDN + 限流；报告内容不可变可长缓存（批次状态更新才失效） |
| 码被复制套牌 | 防伪失效 | 一码一扫风控（§11.2）；H5 显示"第 N 次验证"+ 首扫时间；作废机制 |
| 生产环境多组织协同慢 | 商务 | 一期以平台代理各组织网关签名（记录真实操作人），二期逐步发放各组织独立证书 |
