# 基于 Hyperledger Fabric 联盟链的地方特色食品全链路溯源系统——以保定驴肉火烧为例

# 摘要

驴肉火烧是河北保定最具代表性的地理标志传统食品，其产业链覆盖养殖、屠宰、加工、冷链物流与餐饮门店等多类主体。长期以来产业链数据分散、信息孤岛严重，溯源数据依赖中心化数据库存储、可信度不足，行业内屡有以骡马肉等廉价畜肉冒充驴肉的现象，消费者难以验真，监管部门对食品安全事件的召回定位困难。针对上述问题，本项目设计并实现了一套基于 Hyperledger Fabric 联盟链的地方特色食品全链路溯源系统，并完成了真实联盟链网络的组网与交易验证。

系统采用"前端三端合一 + Spring Boot 服务 + Hyperledger Fabric 联盟链"的五层架构，以联盟链组织映射产业链五类主体，设计了 S（屠宰）—P（加工）—F（成品）父子批次模型与"DT+14 位"一物一码规则，将驴只建档、批次流转、检验、溯源码绑定、召回等 12 类关键业务事件全量上链存证；账本层采用 SHA-256 链式哈希区块结构，提供区块浏览、交易明细与全链完整性校验。在此基础上，项目在真实环境中部署了 Hyperledger Fabric v2.5.16 联盟链测试网络（双组织 Peer 节点 + 排序节点，TLS 加密，Go 语言链码经双组织背书提交），完成了保定溯源记录的真实上链交易：区块高度随交易由 11 增长至 12，链上读回数据与写入内容完全一致，前后区块哈希严格衔接，验证了系统架构向真实区块链网络迁移的可行性。

系统实现了 45 个 REST 接口、19 张业务表与十大功能模块，基于 Playwright 完成 27 个自动化端到端测试并全部通过；完整性校验测试表明，对任何历史数据的篡改均可被准确定位。前端已部署至公有云并绑定自定义域名，任何设备可通过浏览器在线访问。本系统为区域特色食品产业提供了"来源可查、去向可追、责任可究、风险可控"的数字化溯源基础设施，技术路线可复制推广至其他地理标志食品，具有良好的应用前景与社会价值。

**关键词**：区块链溯源；Hyperledger Fabric；联盟链；食品安全；一物一码；全链路追溯

# Abstract

Lürou Huoshao (donkey meat sandwich) is the most representative geographical indication traditional food of Baoding, Hebei Province, whose supply chain involves multiple parties including farms, slaughterhouses, processing plants, cold-chain logistics and restaurants. However, the industry suffers from fragmented data, low credibility of centralized traceability records, frequent adulteration, and difficulties in recall positioning. This project designs and implements a full-chain traceability system for local specialty food based on the Hyperledger Fabric consortium blockchain, and completes the deployment of a real Fabric network with transaction verification.

The system adopts a five-layer architecture of "unified front end + Spring Boot services + Hyperledger Fabric consortium chain". Consortium organizations are mapped to five types of supply-chain entities. An S-P-F parent-child batch model and a "DT + 14-digit" one-item-one-code rule are designed, and 12 categories of key business events are fully recorded on-chain with a SHA-256 hash-chained ledger providing block browsing and integrity verification. Furthermore, a real Hyperledger Fabric v2.5.16 test network (two organizational peers plus an ordering node with TLS enabled, and a Go chaincode endorsed and committed by both organizations) is deployed. A real traceability transaction of a Baoding trace record is committed: the block height grows from 11 to 12, the chain-read data is fully consistent with the written content, and the hashes of adjacent blocks are strictly linked, verifying the feasibility of migrating the system architecture to a real blockchain network.

The system implements 45 RESTful APIs, 19 business tables and 10 functional modules. 27 automated end-to-end test cases based on Playwright all pass. Integrity verification tests show that any tampering with historical data can be accurately located. The front end has been deployed to the public cloud with a custom domain name. The system provides a digital traceability infrastructure of "traceable origin, traceable destination, accountable responsibility and controllable risk" for regional specialty food industries, and its technical route is replicable to other geographical indication foods.

**Key words**: blockchain traceability; Hyperledger Fabric; consortium chain; food safety; one-item-one-code; full-chain traceability

# 一、研究背景与意义

## 1.1 产业现状与溯源痛点

驴肉火烧是我国华北地区极具代表性的传统特色小吃，其中以河北省保定市徐水区漕河镇为代表的"漕河派驴肉火烧"历史悠久，是保定饮食文化的名片。近年来，以保定为中心的驴肉产业链已形成较完整的形态：上游为唐县、易县等山区县的肉驴养殖场，中游为徐水漕河等地的屠宰与卤制加工企业，下游为遍布保定莲池区、竞秀区乃至全国的驴肉火烧门店。

然而，产业链繁荣的背后是规范化程度的不足。肉驴养殖周期长（一般 2~3 年出栏）、单只价值高，驴肉原料价格昂贵且供给紧张，行业内一度存在骡马肉、其他廉价畜肉冒充驴肉的现象；对熟制驴肉制品而言，冷链运输断链、门店来源不明等问题进一步削弱了消费者信任。传统食品安全追溯多依赖纸质台账或企业自建的中心化信息系统，存在四类突出痛点：

1. **信息孤岛**：养殖、屠宰、加工、物流、门店各环节由不同主体经营，数据分散、格式不一，发生食品安全事件时需人工逐环节排查，效率低、误差大；
2. **数据可信度低**：中心化数据库中的记录可被单方修改，溯源数据"自证清白"缺乏公信力，监管部门与消费者难以采信；
3. **召回扩散定位困难**：加工环节的分割、组合使批次之间形成复杂的父子关系，一个污染批次可能扩散至多个下游成品批次与门店，人工定位召回范围费时费力且容易遗漏；
4. **消费者参与度低**：消费者缺少便捷渠道查看所购食品的全链路信息，"一物一码"的验真价值未能充分发挥。

## 1.2 研究意义

本项目将养殖、屠宰、加工、冷链、门店、监管多方纳入同一联盟链网络，关键业务事件以密码学方式上链存证，实现"来源可查、去向可追、责任可究、风险可控"。其意义体现在三个层面：

- **产业层面**：为保定驴肉火烧这一地理标志特色产业提供数字化溯源基础设施，以技术手段治理假冒伪劣乱象，助力区域品牌保护与产业升级，服务乡村振兴；
- **技术层面**：完成了从业务哈希链到真实 Hyperledger Fabric 联盟链的完整落地，验证了联盟链在多主体食品供应链协同中的工程可行性，形成可复制、可推广的技术方案；
- **监管层面**：为监管部门提供证照临期提醒、抽检登记、召回扩散分析、预警处置与数据驾驶舱等穿透式监管工具，推动食品安全治理从"事后处置"向"过程管控"转变。

# 二、国内外研究现状与选题依据

食品溯源体系的研究起步于欧盟。2000 年欧盟颁布 (EC) 178/2002 法规，要求自 2005 年起在欧盟范围内销售的所有食品必须可追溯；国际标准 ISO 22005:2007 给出了饲料与食品链可追溯性的体系设计通用原则；日本在"牛肉追溯制度"中实现了牛肉个体从出生到销售的全流程编号管理。我国相继出台《食品安全法》《农产品质量安全法》及 GB/T 38155—2019 等追溯标准，农业农村部推动实施兽药二维码、检疫电子出证等措施。

区块链凭借去中心化、不可篡改、可追溯的特性，被视为解决多主体溯源数据互信问题的有效手段：IBM Food Trust 联合沃尔玛等零售企业将 Hyperledger Fabric 用于食品供应链溯源，将芒果溯源查询时间从约 7 天缩短至 2.2 秒；国内蚂蚁链、腾讯至信链等亦在食品、农产品溯源领域规模化落地。学术界围绕"区块链 + 食品溯源"的共识是将链上存证与链下业务库结合——原始数据存链下数据库，关键事件的哈希摘要上链，兼顾性能与可信。

综合来看，现有方案存在四点不足：其一，多聚焦单一环节或单一品类，缺乏覆盖"养殖—屠宰—加工—冷链—门店"的多角色联盟化设计；其二，对加工环节批次分裂/聚合形成的父子批次树支持不足，召回扩散分析能力弱；其三，面向监管者的穿透式监管工具往往与业务系统割裂；其四，多数方案止步于原型验证，缺少真实区块链网络环境下的交易验证。本项目针对以上不足进行了针对性设计与完整实现。

# 三、系统总体设计

## 3.1 系统分层架构

系统采用"展示层—应用层—服务层—数据层—区块链层"五层架构（见图 1）：

- **展示层**：基于 Vue 3 + TypeScript + Element Plus 的单页应用，管理端按角色动态装配菜单与路由，并适配消费者的手机端溯源报告页；
- **应用层**：Spring Boot 实现的 RESTful API 服务，提供认证、组织、养殖、批次、物流、门店、溯源、监管等 45 个接口；
- **服务层**：业务逻辑封装，包括权限校验、批次树分析、预警引擎、哈希校验等；
- **数据层**：MySQL 存储 19 张业务表明细，业务表携带链上交易标识（txid/区块高度），保证业务库与链上数据可双向核对；
- **区块链层**：Hyperledger Fabric 联盟链网络与 SHA-256 链式哈希账本，关键业务事件经链码上链。

## 3.2 联盟链网络设计与真实组网

联盟链由五类组织节点组成：平台运营方（排序节点）、养殖场组织、加工厂组织、物流组织与监管机构，各组织持有独立的 MSP（成员服务提供者）身份，加入同一业务通道。链码（智能合约）部署于通道内，提供资产创建、状态流转、事件存证等合约方法；所有业务写操作以交易形式上链，每笔交易获得唯一 TxID 与区块高度。Fabric 采用"执行—排序—验证"架构：背书节点先行模拟执行链码，排序节点全局排序出块，记账节点验证后提交，兼顾吞吐量与最终一致性。

为验证架构的真实可用性，项目在真实环境中完成了 Fabric 联盟链组网（见图 2）：基于 Hyperledger Fabric v2.5.16 部署测试网络，包含 org1、org2 两个组织的 Peer 记账节点与 1 个 Raft 排序节点，全链路启用 TLS 加密；Go 语言编写的链码 basic v1.0 经双组织安装、批准、提交后生效，运行于独立链码容器。该网络已完成多笔真实溯源交易的持续验证。

## 3.3 全链路业务模型

以一头肉驴从养殖到餐桌的旅程为主线，系统覆盖七个环节：养殖场为每头驴建立耳标档案（如 E1306-2025-000301），饲养、免疫、检疫事件逐条上链，出栏检疫的检疫证哈希上链；屠宰场创建屠宰批次（S），记录宰前宰后检验；加工厂创建加工批次（P）进行卤制分割，成品转移至成品批次（F），形成 **S→P→F 父子批次链**；物流商承接冷链运输，按固定间隔上报车厢温湿度、超限自动预警；门店收货入库，制作驴肉火烧时登记产出并为每份成品生成"一物一码"溯源码（DT+14 位）绑定 F 批次上链；消费者扫码查看全链路报告；监管端实现证照临期提醒、抽检登记、基于批次树的召回扩散分析与数据驾驶舱。

S→P→F 父子批次模型是本系统召回能力的核心：任一成品批次可沿血缘树回溯至具体屠宰批次与驴只个体；发生食品安全事件时，系统沿批次树正向分析扩散范围（受影响下游批次、涉及门店、已流通溯源码数），实现精准召回。

## 3.4 区块链存证设计

**链码接口**按业务域划分，覆盖全链路关键操作：

| 链码方法 | 说明 | 调用方 |
|---------|------|--------|
| CreateDonkey | 创建驴只档案 | 养殖场 |
| AddDonkeyEvent | 登记饲养/免疫/检疫事件 | 养殖场 |
| BatchSlaughter / BatchProcess / BatchProduct | 创建 S/P/F 批次 | 屠宰加工厂 |
| ReceiveBatch / TransferBatch | 批次接收与持有人流转 | 物流/门店 |
| QCReport | 出厂检验结论上链 | 质检员 |
| BindTraceCode | 溯源码绑定成品批次 | 门店 |
| InitiateRecall | 发起召回 | 监管机构 |

**SHA-256 链式哈希区块结构**（见图 3）：每个区块包含区块高度 blockNo、出块时间、交易数组（每笔含操作类型、业务摘要 payload、发起组织 MSP、TxID）、前一区块哈希 prevHash 与本块哈希 hash = SHA-256(blockNo + timestamp + 序列化(txs) + prevHash)。任何历史交易的改动都会导致该块哈希变化，进而使其后所有区块的 prevHash 链校验失败。

![图 3 SHA-256 链式哈希区块结构](C:/Users/ZYF/WorkBuddy/2026-09-11-20-14-23/thesis-figs/gen/fig-4-2-hashchain.png)

**完整性校验机制**：从创世块开始逐块重算哈希并与块内 hash 比对，同时校验每块的 prevHash 是否等于前一块的 hash；全部通过输出"校验通过：N 个区块，M 笔交易，哈希链完整"，任一失败则定位首个被篡改的区块高度。溯源报告页对单码关联事件重算详情哈希比对，实现"码级"验证。

## 3.5 数据库与安全设计

数据层共设计 19 张业务表，核心表包括驴只表（耳标号唯一，携带建档 TxID）、批次表（S/P/F 类型自关联父子，携带当前持有人组织与创建 TxID）、溯源码表（DT 码绑定批次与门店，携带绑定 TxID）、运输单表与区块表（链上镜像）等，均含审计字段与链上标识。安全设计采用"角色—权限—菜单"三级 RBAC 模型与动态路由：登录签发 JWT，前端按角色过滤菜单，按钮级权限经自定义指令控制，接口侧双重校验；溯源公开接口列入白名单供消费者免登录查询，并配套扫码风控策略。

## 4.2 业务哈希链账本与存证校验实现

账本服务（ChainService）将账本持久化于 MySQL 区块表，payload 以原样文本存储以避免 JSON 键序重排破坏哈希一致性；哈希输入按字段序拼接后经 SHA-256 计算，时间统一截断到秒以保证存库值与哈希值一致。`appendTx` 在同一业务写接口内先上链、后落库，交易 ID 与区块高度回写业务表；全部 12 类业务写操作（创建驴只、批次、运输单、生成溯源码、召回等）均已挂钩上链，实现"新业务操作 → 账本区块增加"的实时联动。区块链账本页（见图 5）提供统计卡、区块浏览、交易明细抽屉、全链完整性校验与按组织的上链统计。

## 4.3 Hyperledger Fabric 真实联盟链部署与交易验证

在业务哈希链账本之上，项目完成了真实 Hyperledger Fabric 联盟链的部署与端到端交易验证，实施过程如下：

1. **网络组建**：基于 Fabric v2.5.16 启动测试网络，生成 org1、org2 双组织证书体系（MSP）与 TLS CA；启动 orderer 排序节点与两个组织的 peer0 记账节点，创建业务通道并使双组织加入，完成锚节点设置；
2. **链码部署**：开发 Go 语言链码 basic（封装资产创建、读取、状态流转等合约方法），经双组织背书策略安装、批准与提交，链码包在两个组织peer节点各自编译为独立链码容器运行；
3. **真实交易验证**：以双组织背书方式发起 CreateAsset 交易，写入一条保定驴肉火烧溯源记录（TR-2026-1002，关联唐县振海驴业养殖场与加工批次 donkey-fire-batch-20261011），交易返回 status:200；随后以链码查询 ReadAsset 链上读回，内容与写入完全一致；
4. **链式结构核验**：交易前后分别查询通道状态，区块高度由 11 增长至 12，且交易后区块的 previousBlockHash 与交易前区块的 currentBlockHash 严格衔接，证明每笔交易生成真实区块、链式哈希环环相扣。

# 六、项目创新点

1. **全链路一码贯通的批次血缘模型**。设计 S→P→F 父子批次模型与"DT+14 位"一物一码规则，将五类产业链主体纳入同一联盟链，实现"一头驴→一份驴火"的正向溯源与反向召回：任一溯源码可沿批次血缘树回溯至具体驴只个体，任一问题批次可沿血缘树正向计算扩散范围（受影响批次、门店、已流通溯源码数），把召回定位从"人工逐环节排查"变为"一键自动分析"。

2. **双层链架构与真实联盟链落地**。业务层采用 SHA-256 链式哈希账本实现 12 类关键业务事件全量挂钩与秒级完整性校验；在此基础上真实部署 Hyperledger Fabric v2.5.16 联盟链（双组织 Peer + Raft 排序节点 + TLS + Go 链码双组织背书提交），完成真实溯源交易并核验区块高度增长与前后哈希衔接。课程级项目中实现"业务哈希链 + 真实 Fabric"双链验证的完整落地，既保证了系统当前可用性，又打通了向生产级联盟链迁移的路径。

3. **穿透式监管工具与业务数据同源**。证照临期提醒、抽检登记、召回扩散分析、预警中心与暗色数据驾驶舱五件套与业务系统共用同一数据底座，监管数据实时真实，避免"监管系统另建一套账"的信息割裂，实现"一屏观全域、一键管召回"。

4. **工程完整度与真实部署**。系统并非原型演示：45 个 REST 接口、19 张业务表、27 个自动化端到端用例全部通过；前端已上线公有云并绑定域名，任何设备扫码即可访问；Fabric 网络真实运行、交易可独立验证，全链路证据链完整可查。

# 七、应用前景与社会价值

**推广前景**。本系统的技术路线具有强通用性：将链码中的资产模型替换为目标品类、将组织映射替换为对应产业链主体，即可复制至五常大米、阳澄湖大闸蟹、金华火腿等其他地理标志食品的溯源场景。系统采用开源技术栈与免费云基础设施构建，中小微企业与县域产业部门均可低成本落地。

**社会价值**。其一，食品安全治理：以不可篡改的链上存证倒逼各环节规范经营，让假冒驴肉无处遁形，直接回应《食品安全法》对全程追溯制度的要求；其二，乡村振兴与产业升级：肉驴养殖是我国北方山区的重要特色产业，溯源基础设施带来的品牌溢价可直接转化为农户收益，助力"土特产"变成"金招牌"；其三，数字政务实践：穿透式监管工具为基层市场监管部门提供了低成本、可复用的数字化治理样板，推动食品安全治理体系和治理能力现代化。

# 八、结论与展望

本项目面向保定驴肉火烧产业链的溯源痛点，完成了基于 Hyperledger Fabric 联盟链的全链路溯源系统的需求分析、总体设计、编码实现、真实组网与系统测试。主要成果包括：设计了覆盖五类主体的联盟链网络与 S→P→F 批次血缘模型；实现了 12 类关键业务事件全量上链的 SHA-256 链式哈希账本与完整性校验；真实部署了 Fabric v2.5.16 双组织联盟链并完成端到端交易验证（区块高度增长、前后哈希衔接、读回一致、唯一性约束生效）；系统 27 个自动化测试全部通过并已上线公有云演示环境。

后续工作包括：将后端账本提交入口整体迁移至 Fabric Gateway SDK，实现业务链与 Fabric 链的双写锚定；引入物联网温湿度硬件直采与消费者微信小程序端；探索基于链上数据的供应链金融（存货质押）与保险理赔等延伸场景，持续放大区块链溯源的产业价值。
